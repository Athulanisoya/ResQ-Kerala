# Integrated analysis, shelters and safety assistant

The admin report detail page offers **Run integrated analysis**. The default runs the seven read-only evidence tools in order without an LLM. Optionally check **Use the configured local model** to try the local Ollama model for a provisional translation, generative summary and a bounded Agents SDK tool run. The default Ollama server and model are configured by `OLLAMA_BASE_URL` and `OLLAMA_MODEL`; the URL is restricted to a local server. No report text is sent to a remote model by this workflow.

The SDK run must execute each required tool in order. If it fails, times out, skips or repeats a tool, the system discards its narrative and runs the deterministic tools instead; the result identifies that fallback. Failed, unavailable, not-run or uncertain evidence makes the overall result incomplete. Each admin run saves a numbered revision; the history endpoint and UI are administrator-only. Original report text remains unchanged. Translation, generated summaries, model classification and the agent narrative are provisional and always require human review. An absent translation is not a successful translation. There is no guarantee that a local model preserves negation or accurately understands every Malayalam report, and the small number of tests does not establish real-world accuracy.

The shelter and safety assistant is available to signed-in users through the sidebar. It can answer report-status questions using the same owner, assigned-team and admin access boundaries as report details; status lookup is local and does not send case data to a model. If its configured provider is unavailable, it uses a clearly labelled local fallback. Shelter location search never substitutes unrelated records for a location that did not match. Emergency contact results show their source links and should be checked for current information. Repository safety documents and shelter records can be incomplete, stale or awaiting owner approval; the system does not establish official approval or live availability.

Shelters support optional facilities and coordinates. Administrators can add a shelter and assigned shelter teams can update its capacity, occupancy, status, facilities and coordinates. Nearby search requires a user-supplied latitude and longitude and lists only records with stored coordinates, ordered by approximate great-circle distance. It does not determine a user's location automatically. Existing databases receive additive nullable columns for these fields at startup; an incompatible legacy layout still stops safely under the schema compatibility guard.

For local checks, run `python -m pytest backend/tests/test_week4_integration.py tests/test_week4_ui_integration.py backend/tests/test_shelter_assistant_integration.py tests/test_shelter_ui_integration.py`. A live model check requires an installed running local Ollama model and should use synthetic incidents only. This project is a prototype and the tests do not demonstrate fitness for operational emergency decisions.
